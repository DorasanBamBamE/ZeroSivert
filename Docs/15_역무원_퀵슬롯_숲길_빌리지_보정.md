# 15 — 역무원 출발 · 퀵슬롯 연동 · 숲길과 빌리지 보정

작성: 2026-08-21

## 1. 존 출발을 역무원 대화 방식으로 변경

허브의 직접 진입 트리거를 제거하고, 원작처럼 **역무원에게 말을 건 뒤 `출발`을 선택**해야 숲으로 이동하도록 바꿨다.

| 항목 | 적용 내용 |
| --- | --- |
| NPC | `NPC_ZoneDeparture` — 이름 `역무원`, 역할 `Departure` |
| 위치 | 기존 존 출발 지점 `(-29.31, -37.04)` |
| 스프라이트 | TrainWorker 2프레임, 16×16, Point, 무압축 |
| 애니메이션 | 4 FPS 대기 루프 |
| 상호작용 | `E` 대화 → `출발` 버튼 → `Forest` 투입 |
| 직접 트리거 | `directInteraction = false` |

`ZoneEntryPoint.Depart()`를 공개 진입 함수로 정리하고, `NPCInteract`가 같은 NPC 아래의 출발 지점을 `DialogueUI`에 넘긴다. 대화창을 닫은 다음 레이드 데이터를 저장하고 씬을 전환하므로, 같은 프레임 입력으로 창이 다시 닫히거나 출발이 중복되는 문제도 없다.

허브 배경은 NPC가 제거된 `r_hub_clean_2x.png`로 교체했다. 소스 알파를 불투명화한 뒤 Nearest 2배 확대·PPU 32로 가져와 원래 월드 크기를 유지하면서 PPU 16에서 보이던 타일 벌어짐을 줄였다.

허브 상호작용 NPC 최종 구성:

```yaml
NPC_Bartender      : 바텐더
NPC_Doctor         : 의사
NPC_Networker      : 네트워커
NPC_ZoneDeparture  : 역무원
합계               : 4명
```

## 2. 인벤토리와 퀵슬롯 연결

인벤토리에서 소비 아이템 위에 마우스를 올리고 **3 · 4 · 5 · 6**을 누르면 대응 퀵슬롯에 등록된다. 필드에서는 같은 키를 눌러 즉시 사용한다.

```text
인벤토리 열림 : 아이템 Hover + 3~6 → 퀵슬롯 등록
필드          : 3~6 → 등록된 소비 아이템 즉시 사용
```

- 퀵슬롯에는 `Consumable`만 등록된다.
- 슬롯은 `ItemData`를 기억하고 현재 인벤토리 수량을 실시간 표시한다.
- 아이템이 없어지면 수량은 0으로 갱신되며 잘못된 사용을 막는다.
- 씬이 바뀌어도 같은 실행 세션에서는 등록 상태를 유지한다.
- 인벤토리·대화 UI가 열린 동안 필드 사용 입력을 받지 않는다.
- 인벤토리 하단에 등록 방법 안내 문구를 추가했다.

런타임 검증:

```yaml
테스트 아이템 : medkit
사용 전        : 2개 · 체력 50%
퀵슬롯 3 사용  : 1개 · 체력 95%
결과           : 등록 / 수량 차감 / 회복 모두 정상
```

## 3. 숲 지면과 빌리지 스프라이트 보정

숲의 지면 청크 35종과 빌리지 1종, 총 **36종**을 다시 처리했다.

1. 반투명 알파를 `alpha > 0 → 255`로 정규화
2. Nearest 방식 2배 확대
3. PPU 16 → PPU 32로 바꿔 월드 크기 유지
4. Point 필터 · 무압축 · 밉맵 끔
5. 기존 지면 901개 참조를 전부 `Processed2x`로 교체
6. `Ground_Atlas`에 보정 폴더를 추가해 배칭 유지

런타임에서 보정 지면이 아틀라스 텍스처로 패킹되는 것을 확인했다. 구형 `zc_forest_*` 및 `r_b_village_1` 직접 참조는 **0건**이다.

## 4. 빌리지 북쪽 길 연결

북쪽에서 내려오는 길이 마을 앞에서 끊기던 부분에 전용 연결 스프라이트를 만들었다.

```yaml
오브젝트 : RoadConnector_NorthWest
구성      : 3×10유닛 연결 조각 3개
정렬      : sortingOrder -7
경로      : 북쪽 외곽 도로 → 서쪽 울타리 → 마을 입구
```

기존 청크와 같은 숲길 픽셀을 사용하고 2배 Nearest 처리해, 별도 재질이나 흐림 없이 이어진다. 연결 오브젝트는 빌리지 프리팹과 현재 Forest 씬 양쪽에 저장했다.

---

## 5. 빌리지 건물 통과 차단

기존 벽·울타리 CompositeCollider2D는 유지하고, 집 본체가 뚫리던 영역에 `BuildingBlockers`를 추가했다.

| 구분 | 수치 |
| --- | ---: |
| 건물 BoxCollider2D 형상 | 18개 |
| CompositeCollider2D 경로 | 18개 |
| Rigidbody2D | Static |
| 레이어 / 태그 | Obstacle / Obstacle |

4개 대표 건물 중심에서 `Physics2D.OverlapPoint`를 검사해 **4/4 충돌**을 확인했다. 플레이어와 적 모두 건물 본체를 통과할 수 없다.
