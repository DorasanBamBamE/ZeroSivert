# 22 — 숲 성능 프로파일링 · 최적화

작성: 2026-08-22  
상태: Editor 1차 기준선 측정 완료 — Development Build/전투 구간 측정 대기

## 1. 측정 조건

- Unity 6000.2.8f1 Editor Play Mode
- Hub 시작 위치와 Hub → Forest 실제 출발 뒤 Forest 시작 위치
- 화면 배율 1.0
- 단일 안정 프레임 스냅샷
- Console 오류/경고 0/0

Editor 자체 UI와 Profiler 메모리가 포함되므로 빌드 성능을 대신하지 않는다. 특히 Editor의 `GC Allocated In Frame`과 전체 프로세스 메모리는 게임 단독 수치로 해석하지 않는다.

## 4. 해석

- CPU/GPU 프레임 시간은 Editor 시작 위치 기준으로 60 FPS 목표보다 충분히 낮다.
- Forest는 고밀도 프롭 때문에 전체 GameObject 수가 매우 크지만 `PropBlockCuller`가 225블록 중 8블록만 활성화한다.
- SpriteRenderer는 약 7.8%, Collider2D는 약 12.4%만 활성화돼 화면 밖 컬링이 실제로 동작한다.
- 총 GameObject/Transform 수 25,000은 메모리와 씬 전환 시 생성 비용의 핵심 위험이다.
- 단일 시작 위치 수치에는 빌리지, 다수 적 교전, 총알, 루팅 UI 비용이 포함되지 않았다.
- Editor에서 관측된 프레임당 약 18KB GC는 Editor UI/측정 도구 할당이 섞여 있어 Player Build에서 재측정해야 한다.

## 5. 지금 유지할 설정

- `PropBlockCuller` 블록 크기 20유닛 계열과 0.15초 갱신
- 화면 밖 여유 18유닛
- 프롭 블록 GameObject 단위 활성/비활성
- 나무·풀 밀도를 바로 낮추지 않고 빌드 측정 우선
- 야생 무리 4~5, 무리당 3~5 유지

## 6. 다음 측정

- Windows Development Build 1920×1080
- Forest 시작 위치, 중앙, 빌리지, 밴딧 캠프, 다수 교전 각각 30초 이상
- 평균/최저 FPS와 1% low
- GC Alloc/frame 및 프레임 스파이크
- 씬 진입 직후 25,000개 오브젝트 생성 시간
- Forest 재진입을 반복했을 때 메모리 누적 여부
- 총알/시야 Raycast/적 AI를 ProfilerMarker별로 분리
- Props/Ground/Box Atlas의 실제 배칭과 SetPass 변화

## 7. 최적화 후보 순서

1. Development Build에서 동일 수치 재현 여부 확인
2. 프롭을 런타임 전체 Instantiate하지 않고 인접 블록만 지연 생성하는 방식 검토
3. 비활성 블록 재사용과 Forest 재진입 메모리 누적 확인
4. 적 AI 시야/경로 검사 주기 분산
5. 필요할 때만 풀 밀도 단계 감소

현재 기준선만으로 시각 밀도를 낮출 이유는 없다. CPU/GPU보다 전체 오브젝트 생성과 메모리 압력이 먼저 확인할 대상이다.
