## 1. 목표

허브의 배경을 NPC가 모두 지워진 최신 `r_hub.png`으로 교체한다. 허브에는 아래 네 명만 실제 오브젝트로 둔다.

| 오브젝트 | 역할 | 유지할 기능 |
| --- | --- | --- |
| `NPC_Bartender` | 바텐더 | 대화 · 상점 |
| `NPC_Doctor` | 의사 | 대화 · 상점 |
| `NPC_Networker` | 네트워커 | 대화 · 의뢰 |
| `NPC_ZoneDeparture` | 존 출발 담당 | `E` 상호작용 → Forest 진입 |

배경에 박혀 있던 모든 사람 스프라이트는 최신 원본에서 사라진 상태이므로, NPC 표현과 상호작용은 위 네 실제 프리팹만 담당한다.

## 2. 확인한 현재 상태

### 배경

| 항목 | 현재 | 교체 대상 |
| --- | --- | --- |
| 이미지 | 기존 `Assets/4.Sprite/r_hub.png` | 제공한 `C:/Users/m/Desktop/Hub/r_hub.png` |
| 크기 | 2300×1500 px | 2300×1500 px |
| NPC 포함 | 다수의 원작 NPC가 배경에 박혀 있음 | **NPC 스프라이트 제거됨** |
| 알파 | `64 / 128 / 255`가 섞여 있음 | 동일하게 보정 필요 |
| 현재 PPU | 16 | 원본 비율을 유지한 32(2× 출력) |

`64`와 `128` 알파는 숲 청크에서 확인했던 것과 같은 룸 에디터 격자 흔적이다. PPU가 16이라서 생긴 문제가 아니라, 그 반투명 픽셀이 배경색과 섞이면서 타일이 벌어진 것처럼 보이는 문제다.

### 현재 기능 오브젝트

현재 Hub 씬에는 바텐더·의사·네트워커와 `ZoneEntry`가 이미 존재한다. 그러나 배경 스프라이트의 피벗/스케일이 최신 원본 기준과 일치하지 않아, 최신 배경을 적용할 때는 좌표를 그대로 믿지 않고 **원본 픽셀 앵커에서 다시 산출**해야 한다.

현재 임시 좌표(재배치 전 참고):

```yaml
NPC_Bartender : (3.00, 4.00)
NPC_Doctor    : (8.30, 5.20)
NPC_Networker : (-41.91, -18.57)
ZoneEntry     : (-29.31, -37.04)
```

## 3. 배경 보정 방식

### ① 알파 구멍 제거

최신 원본을 복사해 작업용 `r_hub_clean_2x.png`을 만든다.

```text
alpha > 0 → 255
```

검은 영역도 맵 배경으로 의도된 불투명 픽셀이므로 지우지 않는다. 이 과정은 알파가 64/128인 격자만 제거한다.

### ② 최근접 2배 업스케일

보정된 2300×1500 원본을 **Nearest Neighbor 2배**로 4600×3000으로 만든다.

```yaml
출력 PPU          : 32
월드 크기          : 143.75 × 93.75 유닛 (기존 2300/16, 1500/16과 동일)
필터              : Point
압축              : None
Mipmap            : Off
Wrap Mode         : Clamp
Sprite Mesh Type  : Full Rect
피벗              : Center
```

2배 이미지와 PPU 32는 원본 16px 타일의 실제 월드 크기를 바꾸지 않는다. 다만 픽셀 그리드가 더 안정적으로 유지되어 카메라 이동 때의 벌어진 경계/반투명 틈을 막는다. `PixelPerfectCamera`의 기준 PPU 16은 플레이어·NPC 스프라이트 기준으로 그대로 둔다.

### ③ 배경 전환 원칙

기존 원본은 삭제하거나 덮어쓰지 않는다.

```text
Assets/4.Sprite/Hub/Source/     ← 제공 원본 보존
Assets/4.Sprite/Hub/Processed/  ← alpha 보정 + 2× 출력
Assets/2.Model/Prefabs/Hub/     ← 배경 및 4 NPC 프리팹
```

Hub 씬의 `r_hub_0`는 가공본 하나만 렌더한다. 겹친 구판 배경은 비활성화 후 검증이 끝나면 제거한다.

## 4. NPC 원본 위치 재배치

새 배경은 중심 피벗으로 고정한다. 원작 이미지에서 고른 발밑 픽셀 `(px, py)`를 다음 공식으로 월드 좌표로 변환한다.

```text
worldX = (px - 2300 / 2) / 16
worldY = (1500 / 2 - py) / 16
```

2배 출력에서는 앵커도 2배가 되지만 PPU가 32이므로 위 좌표 결과가 동일하다. 따라서 위치가 이미지 확대 여부에 흔들리지 않는다.

각 NPC는 문턱이나 카운터의 **플레이어가 서는 쪽**이 아니라, 원작에서 캐릭터 발이 놓인 픽셀에 둔다. CircleCollider2D는 발밑만 막고, 상호작용 반경은 카운터 너머에서도 대화가 가능하도록 확인한다.

| 순서 | 대상 | 배치 및 검증 |
| --- | --- | --- |
| 1 | 바텐더 | 원작 바텐더 카운터 앞 발 위치. 상점 제목이 `바텐더`인지 확인 |
| 2 | 의사 | 원작 의무실 카운터 앞 발 위치. 상점 제목이 `의사`인지 확인 |
| 3 | 네트워커 | 원작 의뢰 담당 위치. 대화/의뢰 UI 및 애니메이터 확인 |
| 4 | 존 출발 NPC | 출입구 담당 위치. 대화 대신 `E — 숲으로 출발` 안내와 Forest 전환 확인 |

`ZoneEntry`는 독립된 빈 트리거가 아니라 출발 NPC의 자식 트리거로 정리한다. 이로써 화면에는 NPC가 한 명 보이고, 기능은 기존 `ZoneEntryPoint`를 그대로 재사용한다.

## 5. 허브 공간 구현 순서

1. 최신 원본의 알파 분포를 다시 검사하고 가공본을 생성한다.
2. 가공본을 Point·무압축·PPU 32로 임포트하고, 씬에서 구판 `r_hub_0`와 한 프레임씩 겹쳐 위치/크기를 비교한다.
3. 구판 배경을 최신 배경으로 교체하고, 원본 픽셀 앵커를 기준으로 네 NPC를 배치한다.
4. 네 NPC의 `SpriteRenderer` 층, 발밑 콜라이더, 상호작용 거리, 실제 이동 차단을 확인한다.
5. 존 출발 NPC의 트리거가 Forest만 전환하며, 상점·의뢰 UI와 충돌하지 않는지 확인한다.
6. 플레이 모드에서 카메라 이동/정지 화면을 여러 위치에서 캡처하여 이음새·흔들림·검은 외곽 노출을 확인한다.
7. 콘솔 오류·경고 0건, 배경 1장, 실제 NPC 4명만 존재하는지 최종 집계한다.

---

## 6. 이번 작업에서 하지 않는 것

- 원작의 모든 배경 NPC를 실제 NPC로 복원하지 않는다.
- 허브 내부의 각 방에 별도 전투·루팅·적 스폰을 넣지 않는다.
- 배경 이미지를 타일 수백 장으로 분해하지 않는다. 허브는 보정된 단일 배경 + 필요한 실제 오브젝트만 사용한다.
- 카메라 기준 PPU 16, 플레이어/적 스프라이트 PPU 16은 변경하지 않는다.
