## 5. 3순위 — 성능 최적화

현재 프롭 밀도는 원작 재현을 위해 크게 올린 상태다. 시각 품질을 유지하면서 실제 빌드 성능을 확인해야 한다.

### 5-1. 프로파일링

- [x] Unity Profiler로 Hub/Forest의 1차 Editor CPU·GPU·렌더/오브젝트 규모 기록
- [ ] 에디터가 아닌 Windows Development Build에서도 측정
- [ ] 숲 중앙·빌리지·구조물 밀집 지역·전투 중 프레임 비교
- [ ] `SpriteRenderer`, `Collider2D`, 물리 쿼리, 적 AI 비용 분리 측정
- [ ] Props/Ground/Box Atlas 배칭이 유지되는지 확인

진행 메모 (2026-08-22): Hub는 CPU 3.25ms/GPU 0.45ms/17 draw call, Forest 시작 지점은 CPU 2.96ms/GPU 1.84ms/53 draw call로 측정됐다. Forest는 전체 Transform 25,000개 중 2,591개, SpriteRenderer 23,107개 중 1,812개, Collider2D 5,349개 중 663개만 활성화돼 블록 컬링이 동작했다. Editor 단일 프레임 수치이므로 Development Build와 전투/빌리지 측정 전에는 최종 성능으로 확정하지 않는다. 상세는 22번 문서를 참조한다.

권장 목표:

```yaml
해상도          : 1920×1080
목표 FPS        : 60
프레임 타임      : 평균 16.7ms 이하
콘솔 GC 경고     : 0
플레이 중 메모리 증가 : 지속 누적 없음
```

### 5-2. 필요할 때 적용할 최적화 순서

1. 화면 밖 풀 렌더러 컬링 범위 조정
2. 풀 밀도만 단계적으로 감소
3. 프롭 블록 단위 활성/비활성 범위 조정
4. 나무 콜라이더의 물리 레이어와 쿼리 범위 축소
5. 적 AI의 탐색·시야 검사 주기 분산
6. 반복 생성 오브젝트 풀링 검토

큰 나무와 작은 나무 밀도는 길 찾기와 가시성에 직접 영향을 주므로 풀보다 나중에 낮춘다.
