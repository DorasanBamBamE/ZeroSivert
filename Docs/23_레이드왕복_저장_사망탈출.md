# 23 — 레이드 왕복 · 저장 · 사망/탈출

작성: 2026-08-22  
상태: 정상 탈출/사망 왕복, 디스크 저장, 장비·탄약·퀵슬롯 세부 검증 완료

## 1. 정상 탈출 왕복

Hub Play Mode에서 다음 런타임 테스트 데이터를 만든 뒤 실제 역무원 출발 경로로 Forest에 진입했다.

- 고철 7개
- 루블 1,123
- 레벨 1 / 현재 경험치 37
- 바텐더 퀘스트 1개 수락

Forest에서 고철 2개를 추가로 획득한 상태를 만든 뒤 `ExtractionZone.Extract()`와 동일한 경로로 정상 탈출했다.

```yaml
Forest 진입 고철       : 7
Forest 획득 추가       : 2
Hub 복귀 고철          : 9
Hub 복귀 루블          : 1,123
Hub 복귀 경험치        : 37
Hub 복귀 활성 퀘스트    : 1
RaidCount              : 1
RunData/Wallet/Quest/Level 인스턴스 : 각 1개
```

Hub 복귀 직후 생존 결과 화면이 열리면서 `Time.timeScale = 0`이 되는 것은 의도된 동작이다. 최소 표시 시간이 지난 뒤 `Skip()`으로 닫으면 결과 화면이 꺼지고 `Time.timeScale = 1`로 복구됐다.

## 2. 사망 왕복

별도 Play Mode에서 다음 데이터를 만든 뒤 Hub → Forest로 출발하고 플레이어 사망 처리를 호출했다.

- 고철 7개
- 루블 1,055
- 경험치 23
- 활성 퀘스트 1개

사망 결과 화면을 넘겨 Hub로 돌아온 결과:

```yaml
고철                  : 0
RunData.HasSnapshot   : false
RunData.LastOutcome   : Died
루블                  : 1,055 유지
경험치                : 23 유지
활성 퀘스트            : 1 유지
RunData/Wallet/Quest/Level 인스턴스 : 각 1개
Time.timeScale        : 1
```

현재 정책은 사망 시 레이드 인벤토리/스탯 스냅샷을 버리고, 벙커 보관 성격인 지갑·레벨·퀘스트는 유지한다.

## 3. 발견한 Forest UI 오류

첫 사망 검사에서 다음 오류가 발생했다.

```text
Coroutine couldn't be started because the game object 'RunEndScreen' is inactive
```

`RunEndScreen` 스크립트 문제가 아니라 Forest 씬의 메인 `Canvas` 루트가 비활성 상태였던 것이 원인이었다. 자식 `RunEndScreen`은 activeSelf가 true여도 부모가 꺼져 있어 다음이 모두 막혔다.

- HUD 표시
- RunEndScreen `Update`
- 페이드 코루틴
- 키보드 결과 화면 건너뛰기

Forest의 루트 `Canvas`를 활성화해 저장했다. 수정 후 재검사에서:

- Forest Canvas activeInHierarchy = true
- RunEndScreen isActiveAndEnabled = true
- 사망 결과 화면 열림
- 시간 정지 0
- Skip 뒤 Hub 복귀 및 시간 1
- 콘솔 오류/경고 0/0

추가로 `Assets/Screenshots/forest_hud_runtime.png`를 촬영해 HP/스태미나, 상태 아이콘, 퀵슬롯이 실제 Game View의 정상 위치에 표시되는 것을 확인했다. Canvas 활성화 시 일부 자식 `RectTransform`의 직렬화 값은 Layout 시스템이 구동하는 값으로 정리되지만 실행 화면 배치는 정상이다.

## 4. 확인된 보존 범위

- `RunData.PlayerSnapshot`: 체력/스태미나/생존 스탯, 인벤토리, 장비 목록, 활성 무기 인덱스
- `Wallet`: DontDestroyOnLoad, 사망 유지
- `PlayerLevel`: DontDestroyOnLoad, 사망 유지
- `QuestManager`: DontDestroyOnLoad, 사망 유지
- `QuickSlotBar`: 현재는 정적 `savedBindings[4]`로 같은 실행 세션의 씬 전환 동안 등록 유지

## 5. 남은 작업

- 장비 4칸, 활성 무기, 탄창/예비 탄약을 실제 값 변경 후 왕복 검증
- 퀵슬롯 선택/등록을 세션 정적 배열이 아니라 디스크 저장 데이터에 포함
- 무기 숙련도와 통계의 Forest → Hub 유지 확인
- 정상 탈출 결과 화면의 처치·루팅·시간·경험치 값 직접 시각 확인
- 사망 원인 문구와 경험치 표시 직접 시각 확인
- 새 게임/계속하기 저장 파일 포맷과 버전 필드 구현
- 씬 왕복 5회 이상 반복 시 메모리/매니저 중복 검사

## 6. 사용자가 직접 확인할 항목

- Forest에서 실제 아이템을 주운 뒤 탈출해 Hub 인벤토리에 남는지
- 사망 결과 화면의 페이드와 버튼/키 건너뛰기가 자연스러운지
- 사망 뒤 인벤토리는 사라지고 루블·레벨·퀘스트는 남는 정책이 원하는 방향인지
- 생존/사망 결과 화면 문구와 수치가 읽기 쉬운지

## 7. 2026-08-22 디스크 저장 및 최종 사망 재검증

후속 작업에서 JSON 저장을 구현하고 다음 항목을 실제 에디터 재시작 왕복으로 확인했다.

- 인벤토리 위치·회전·수량
- 장비 4칸, 활성 무기, 무기별 탄창과 예비탄
- 퀵슬롯, 루블, 레벨/경험치, 통계, 무기 숙련도
- 활성/완료 퀘스트와 킬 진행도, 일일 의뢰, 게임 시간
- 레이드 횟수와 마지막 결과

최종 사망 경로는 `MainTitle → Hub → Forest → PlayerStats 사망 이벤트 → RunEndScreen → Skip → Hub`로 다시 실행했다. Hub 복귀 후 기존 레이드 스냅샷은 버려지고 Makarov 8발, 소형 탄약 90발, 붕대·통조림·물병이 지급됐다. 에디터를 정지하고 다시 `계속하기`로 들어간 뒤에도 같은 상태, `Outcome.Died`, `RaidCount 1`이 복원됐으며 콘솔 오류/경고는 0/0이었다.

세부 구현과 빌드 결과는 `24_구조물깊이_탄약_디스크저장_AI빌드검증.md`를 참조한다.

## 8. MainTitle 선행 매니저 생성 회귀 수정

저장이 있는 상태로 MainTitle을 시작하면 저장 적용 코드가 `Wallet.Instance`, `GameClock.Instance`, `QuestManager.Instance`를 호출해 독립 오브젝트를 먼저 만들었다. 이후 Hub의 통합 `GameManager`가 로드될 때 각 싱글톤의 중복 처리에서 `GameManager` 오브젝트 전체가 파괴되어 같은 오브젝트의 `PlayerLevel`과 `GameStats`도 사라지는 문제가 실제 퀘스트 보상 검사에서 발견됐다.

`SaveGameManager.ApplyGlobalProgress`가 현재 씬에 이미 존재하는 컴포넌트만 찾아 갱신하도록 수정했다. 수정 후 결과:

```yaml
MainTitle 선행 Wallet/GameClock/QuestManager : 각 0
Hub GameManager                             : 존재
Hub Wallet/GameClock/QuestManager           : 각 1
Hub PlayerLevel/GameStats                   : 각 1
퀘스트 경험치 지급                           : 정상
저장 후 재시작 퀘스트 진행                    : 1 유지
콘솔 오류/경고                              : 0 / 0
```
