# 28 — 허브 충돌 · 제작 · 탄종 선택 · 타이틀 3버튼

작성: 2026-08-23  
상태: 구현 및 자동 회귀 검사 완료 — 사용자 직접 체감 확인 대기

## 허브 충돌 수정

- 남쪽 벙커 입구를 플레이어 폭 기준 3셀 통로로 개방했다.
- 동쪽 병실 2곳의 바닥과 중앙 진입 통로를 개방했다.
- 청색 타일 방과 휴게실 바닥을 이동 가능 영역으로 복원했다.
- 병실 침대 4개와 휴게실 소파 2개는 별도 장애물로 다시 배치해 가구 관통을 막았다.
- 최종 PolygonCollider2D는 98개 경로다.
- 플레이어 시작점 기준 자동 경로 검사: 입구, 병실 A/B, 청색 방, 휴게실 모두 도달 가능.
- 주요 허브 비트리거 콜라이더 16개에 Concrete/Metal/Wood 재질 태그를 저장했다.

## 탄종 선택과 HUD

- 같은 구경 탄약을 인벤토리에서 우클릭하면 해당 탄종을 선택한다.
- 기존 탄창에 실제 탄종이 남아 있으면 인벤토리로 반환한 뒤 선택 탄종을 재장전한다.
- 초기 구형 무기의 타입 없는 무료 탄창은 아이템 복제를 막기 위해 선택 시 비운다.
- HUD에 장전/선택 탄종 이름과 관통 수치를 표시하고 관통력이 높을수록 색을 달리한다.
- 임시 인벤토리 시험: 5.45×39mm PS 40발 중 탄창 30발/예비 10발로 정확히 장전.

## 허브 작업대

- 배경의 기존 작업대 위치 `(-10.7, -16.2)`에 상호작용 트리거를 추가했다.
- E로 열고 E 또는 Escape로 닫는다.
- 제작식:
  - 볼트와 너트 3 + 구리선 2 → 5.45×39mm BP 30발
  - 강력 테이프 1 + 의료용 알코올 1 → 멸균 붕대 2개
  - 멸균 붕대 2 + 과산화수소 1 + 강력 테이프 1 → 야전 구급킷 1개
- 제작 성공 시에만 재료를 소모한다.
- 결과물을 전부 넣을 공간이 없으면 추가된 일부 결과물을 되돌리고 재료를 보존한다.
- 자동 시험: 정상 제작 결과 30발/재료 0, 재료 부족 시 제작 실패 및 기존 수량 보존.

## 타이틀

- 메인 화면 버튼을 `Play / Exit / Config` 세 개로 고정했다.
- Play를 누르면 `LOAD GAME / NEW GAME / BACK` 선택창이 열린다.
- 저장이 없으면 LOAD GAME을 비활성화한다.
- 저장이 있는 상태의 NEW GAME은 두 번째 클릭까지 실제 초기화를 실행하지 않는다.
- Exit는 현재 진행을 저장하고 종료한다.
- Config는 전체/음악/효과음과 해상도를 제공한다. 사용자 피드백에 따라 전체화면 항목은 노출하지 않는다.
- 런타임 검사에서 메인 3버튼과 두 패널의 표시 전환, 저장 감지, 콘솔 오류 0건을 확인했다.

## 사용자가 직접 확인할 항목

1. 허브 남쪽 입구, 병실 두 곳, 청색 방, 휴게실을 실제 이동해 벽 끼임이 없는지.
2. 침대·소파·열차·상자에는 막히고 열린 문과 복도는 통과되는지.
3. 인벤토리에서 같은 구경의 일반탄/AP탄을 우클릭한 뒤 HUD 이름·관통 수치와 실제 재장전이 맞는지.
4. 허브 작업대에 접근했을 때 E 안내가 보이고 세 제작식의 성공/부족 안내가 자연스러운지.
5. 타이틀에 Play/Exit/Config만 보이며, Play의 불러오기/새 게임과 Config 복귀가 정상인지.
6. 새 게임 두 번째 확인은 기존 저장을 초기화하므로 필요한 저장을 불러와 확인한 뒤 마지막에 시험할 것.

## 2026-08-23 사용자 피드백 수정

- 탄약 아이콘 아래에 추가했던 탄종 이름/관통 설명 Text는 불필요하다는 피드백에 따라 완전히 제거했다. 탄종 우클릭 선택과 실제 탄도 수치는 유지한다.
- 역무원 `NPC_ZoneDeparture`의 비어 있던 `prompt`와 `dialogue` 참조를 수정했다. 다른 NPC와 동일한 `Prompt_E` 월드 말풍선을 연결했고 범위 진입 시 활성화되는 것을 확인했다.
- 의료 작업대 왼쪽의 북→남 출입구에서 문턱 한 줄에 남아 있던 충돌 셀 2개를 제거했다. 중심선 `x=-15.375`, `y=-14.7~-16.7`을 0.05유닛 간격으로 검사한 결과 잔여 충돌은 0개다.
- MainTitle의 `InputSystemUIInputModule`을 프로젝트의 기존 `Input` 사용 방식과 맞는 `StandaloneInputModule`로 교체했다.
- 실제 UI 포인터 클릭 이벤트로 Play 메뉴와 Config 패널이 모두 활성화되는 것을 확인했다.
- 수정 후 Hub와 MainTitle 런타임 콘솔 오류/경고는 0/0이다.

## 2026-08-23 인벤토리 및 설정 UI 후속 수정

- 인벤토리 하단 퀵슬롯 등록 안내는 글자 크기를 8에서 6으로 낮추고, 하단 퀵바와 겹치지 않도록 위치를 `y=64`, 영역을 `260×12`로 조정했다.
- 런타임 화면 좌표 검사에서 안내 영역 `y=256~304`, 퀵바 영역 `y=24~96`으로 서로 겹치지 않음을 확인했다.
- 인벤토리의 무기 아이템 이미지는 점유 칸 크기의 82%로 표시한다. 소모품·탄약 등 다른 분류와 장착 무기 슬롯은 기존 크기를 유지한다.
- 임시 AK74(4×2칸) 런타임 검사에서 아이콘이 예상값 `52.48×26.24`로 표시되는 것을 확인한 뒤 임시 데이터는 즉시 제거했다.
- 타이틀 설정의 전체화면 토글을 제거하고 패널을 `720×650`으로 재배치했다. 기존 전체화면 저장값은 설정 적용 시 임의로 바꾸지 않는다.
- 설정 패널의 활성 직계 UI 요소 전부를 월드 좌표로 검사해 패널 밖으로 벗어난 요소 0개, 전체화면 관련 UI 0개를 확인했다.
- 실제 포인터 클릭으로 Config 열기, 취소 복귀, 다시 열기, 적용 후 복귀를 검사했으며 모두 정상 동작했다.
- 최종 런타임 콘솔 오류/경고는 0/0이다.
- Windows 64비트 Development 빌드 `Builds/Windows_InventorySettingsQA/ZeroSivert.exe`가 오류 0건으로 성공했다. 빌드 보고서의 경고 487건은 `com.unity.ai.inference`(Sentis) 패키지 셰이더 변형 컴파일 경고가 대부분이며 이번 UI 수정 코드의 컴파일 오류는 아니다.
