# 29 — 타이틀·레이드 왕복·저장 통합 QA

작성: 2026-08-23  
상태: 실제 런타임 통합 흐름 검증 및 발견 결함 수정 완료

## 검증한 전체 흐름

1. MainTitle의 Play에서 저장 감지와 LOAD GAME 활성화를 확인했다.
2. NEW GAME 첫 클릭 경고와 두 번째 클릭 초기화를 실제 UI 포인터 이벤트로 확인했다.
3. Hub 진입 후 Makarov, 9×18mm FMJ 90발, 붕대 2개, 음식 2개, 물 2개 지급과 즉시 저장을 확인했다.
4. 역무원 범위에서 `Prompt_E`가 활성화되고 대화창에 `출발` 버튼이 나타나는 것을 확인했다.
5. 출발 버튼 클릭 후 Forest로 전환되고 인벤토리·장착 무기·스냅샷이 유지되며 레이드 횟수가 1 증가하는 것을 확인했다.
6. ExtractionZone 범위에서 안내와 진행바가 활성화되고, 탈출 완료 후 Hub로 복귀해 `생존함` 결과 화면이 나타나는 것을 확인했다.
7. 결과 화면 건너뛰기, MainTitle 복귀, LOAD GAME 후 장비·인벤토리·레이드 횟수 유지를 확인했다.

## 발견 및 수정한 결함

- 탈출 결과 화면이 메모리에서는 소비되지만 저장 파일의 `lastOutcome=Extracted`가 남아 LOAD GAME 때 다시 나타났다.
- `RunEndScreen.Start()`가 생존 결과를 소비한 직후 `SaveGameManager.SaveNow(false)`를 호출하도록 수정했다.
- 수정 후 최초 Hub 복귀에서는 `생존함` 화면이 열리고, 저장 파일의 결과값은 즉시 None으로 기록된다.
- 이후 MainTitle에서 다시 LOAD GAME 했을 때 결과 화면이 재등장하지 않고 `timeScale=1`로 정상 시작한다.

## QA 환경과 저장 보존

- Codex의 비포커스 상태에서도 프레임이 진행되도록 테스트 중에만 `Application.runInBackground=true`를 런타임 값으로 사용했다. 프로젝트 설정은 변경하지 않았다.
- 실제 사용자 저장의 primary/backup을 `Library/CodexE2EBackup_20260823_2315`에 먼저 복사했다.
- 통합 QA는 별도의 새 게임 데이터로 수행했다.
- QA 종료 후 원래 `savegame.json`과 `savegame.backup.json`을 복원했으며 두 파일 모두 백업과 바이트 단위 일치를 확인했다.
- 최종 런타임 콘솔 오류/경고는 0/0이다.
- Windows 64비트 Development 빌드 `Builds/Windows_E2EQA/ZeroSivert.exe`가 오류 0건으로 성공했다. 경고 486건은 기존 Unity Sentis 패키지 셰이더 변형 컴파일 경고다.

## 사용자가 직접 확인할 항목

1. MainTitle에서 LOAD GAME으로 기존 저장이 정상적으로 열리는지.
2. 새 게임은 기존 저장을 초기화하므로 필요할 때만 두 번째 확인 클릭을 시험할 것.
3. 역무원에게 다가갔을 때 말풍선과 대화창의 출발 버튼이 자연스럽게 보이는지.
4. Forest 탈출 후 `생존함` 화면은 한 번만 나타나고, 다시 LOAD GAME 했을 때 반복되지 않는지.

## 배포

- Git 커밋과 GitHub 업로드는 수행하지 않았다.
