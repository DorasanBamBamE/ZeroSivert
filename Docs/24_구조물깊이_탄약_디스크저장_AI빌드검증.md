## 2. 구조물 깊이

`StructureDepthBands`가 구조물 스프라이트의 실제 `textureRect`를 기준으로 16픽셀 높이 전경 마스크를 생성한다. 원본 구조물 본체는 낮은 정렬 순서를 유지하고, 전경 밴드는 Custom Axis Y 정렬을 사용한다.

적용 프리팹:

- `ZC_forest_bandit_10x10_4`, `6`, `7`
- `ZC_forest_bandit_15x15_1`, `2`, `3`, `4`
- `ZC_village_1`

런타임에서 구조물 15개와 전경 밴드 225개가 생성됐으며, 플레이어가 건물 앞에 있을 때는 전면에 보이고 뒤에 있을 때는 상단 구조물에 가려지는 것을 캡처로 확인했다.

## 4. 디스크 저장

저장 파일은 `Application.persistentDataPath/savegame.json`에 쓰며, 기존 파일 교체 시 `savegame.backup.json`을 남긴다. 임시 파일에 먼저 기록한 뒤 교체해 중간 종료에 의한 손상을 줄였다.

저장 대상:

- 플레이어 체력·스태미나·허기·갈증·에너지·방사능·출혈
- 인벤토리 위치·회전·수량
- 장비 4칸, 활성 무기, 무기별 탄창
- 퀵슬롯 4칸
- 루블, 레벨, 일반/레이드 경험치
- 게임 통계와 무기 숙련도
- 활성/완료 퀘스트, 킬 진행도, 평판, 일일 의뢰
- 날짜·시간, 레이드 횟수와 마지막 결과

모든 `ItemData`와 `QuestData`에는 GUID 기반의 안정적인 `itemId`/`questId`를 부여했다. 씬 로드 직후 한 프레임 뒤 데이터를 적용해 `GameClock`, `Wallet`, `QuestManager`가 Hub의 `GameManager`보다 먼저 만들어져 전체 매니저를 파괴하던 초기화 순서 문제도 방지했다.

후속 퀘스트 보상 검사에서 한 프레임 지연만으로는 충분하지 않다는 회귀를 다시 발견했다. 저장이 있는 MainTitle 자체에서 지연 적용이 실행되면서 독립 매니저가 먼저 만들어졌기 때문이다. `ApplyGlobalProgress`를 생성형 `Instance` 접근 대신 현재 씬에 이미 존재하는 컴포넌트 조회 방식으로 변경했다. 수정 후 MainTitle에서는 선행 매니저 0개, Hub에서는 통합 `GameManager`와 `PlayerLevel/GameStats/Wallet/GameClock/QuestManager`가 각 1개로 유지된다.

런타임 왕복 검증:

```yaml
장비             : SVT-40 복원
탄창/예비탄       : 3 / 7 복원
퀵슬롯           : 붕대 복원
루블             : 4,321 복원
레벨/경험치       : 4 / 123 복원
발사 통계         : 42 복원
소총 숙련도       : 레벨 5 / 경험치 4 복원
퀘스트            : 골칫거리 정리, 진행 1 복원
```

## 5. 새 게임과 사망 복귀

MainTitle의 기존 버튼을 위에서부터 다음 동작으로 연결했다.

1. 저장이 없으면 `게임 시작`, 있으면 `계속하기`
2. `새 게임`
3. `종료`

기존 저장이 있을 때 `새 게임`을 한 번 누르면 저장을 삭제하지 않고 버튼 문구가 4초 동안 `새 게임? 다시 누르기`로 바뀐다. 이 시간 안에 다시 눌러야 실제 초기화되며, 시간이 지나면 원래 문구로 복귀한다.

새 게임 또는 사망 후 스냅샷이 없는 빈 플레이어에는 다음 최소 장비를 지급한다.

- Makarov, 탄창 8발
- 소형 탄약 90발
- 붕대 2, 통조림 2, 물병 2
- 퀵슬롯: 붕대·통조림·물병

2026-08-22 최종 사망 재검증:

```yaml
경로              : MainTitle → Hub → Forest → 사망 → 결과 화면 → Hub
사망 결과 화면      : 열림, Time.timeScale 0
건너뛰기 후         : Hub, Time.timeScale 1
복귀 장비           : Makarov 8 / 예비탄 90, 인벤토리 슬롯 6
RunData outcome    : Died
RaidCount          : 1
에디터 재시작 계속하기 : 같은 장비·탄약·결과·횟수 복원
콘솔 오류/경고      : 0 / 0
```

## 5-1. 퀵슬롯 해제

- 인벤토리에서 소비품에 마우스를 올리고 `3~6`: 등록 또는 교체
- 인벤토리가 열린 상태에서 `Shift+3~6`: 해당 슬롯 해제
- 아이템 수량이 0이면 등록은 유지하되 아이콘만 비활성화하고, 같은 아이템 재획득 시 다시 활성화

Hub에서 비활성 계층의 QuickBar도 찾아 슬롯 0을 붕대에서 빈 상태로 해제했고, 디스크 저장과 에디터 재시작 뒤에도 슬롯 0은 비어 있고 슬롯 1의 통조림은 유지되는 것을 확인했다.

## 5-2. 퀘스트와 상점 회귀 검사

실제 `EnemyHealth.Die → EnemyIdentity.ReportDeath → QuestManager.ReportKill` 경로로 Forest Bandit 한 명을 처치해 `골칫거리 정리` 진행도가 0에서 1로 증가하고, 저장 후 재시작에도 1이 유지되는 것을 확인했다.

```yaml

밴딧 처치 의뢰 : 8회 진행, 루블 +1,000, 경험치 +250
일일 의뢰      : 3개 추첨, 중복 0
```

상점 거래 검사:

```yaml

같은 붕대 판매      : 계산가 135, 실제 지급 135
루블 0 구매 시도    : 이동 취소, 재고 수량 유지, 필요 금액 안내
```

## 6. 적 AI와 전투

`EnemyControllerBase`에 0.75초 정체 감지와 좌우 교대 측면 이동을 추가했다. 한 Forest 시드의 적 103마리 가운데 92마리가 관측 구간 동안 0.5유닛 이상 이동했고, 이동 속도만 남은 채 정지한 적과 경계 상태 영구 정지 적은 0마리였다.

- 열린 시야: 적 총알 활성화와 플레이어 피해 확인
- 구조물 충돌체 뒤: `HasLineOfSight = false`, 활성 총알 0, 적 탄약·플레이어 체력 변화 없음
- Bullet: Kinematic Rigidbody2D, Continuous, Trigger, 풀링 유지

## 7. 빌드와 씬 검증

Windows 64-bit Development Build:

```yaml
출력              : Temp/CodexBuild/ZeroSivert.exe
결과              : 성공
상세 보고 총크기    : 약 329.22 MB
빌드 오류          : 0
프로젝트 C# 오류    : 0
```

Hub UI와 PDA 후속 수정까지 포함한 최종 빌드 작업 `build-3f5da10299`는 17.79초, 오류 0, 경고 486건으로 성공했다. 경고는 주로 Sentis 셰이더 컴파일, URP/AppUI 전처리, 빌드 중 MCP 시간 초과다. `-batchmode -nographics`로 10초 구동한 `C:/Users/rnrqk/AppData/Local/Temp/ZeroSivertPlayerTestFinal.log`에는 C# 예외, `NullReferenceException`, `MissingReferenceException`이 없었다. Null 그래픽 장치의 미지원 셰이더 메시지는 실제 그래픽 실행 결과로 사용하지 않는다.

Unity MCP 씬 검증 결과:

```yaml
MainTitle : 문제 0 / Missing Script 0 / Broken Prefab 0
Hub       : 문제 0 / Missing Script 0 / Broken Prefab 0
Forest    : 문제 0 / Missing Script 0 / Broken Prefab 0
```

Unity Test Framework의 EditMode/PlayMode 루트 스위트도 모두 `Passed`였지만, 프로젝트에 등록된 실제 개별 테스트 케이스는 현재 0개다. 따라서 이 결과는 자동 단위 테스트의 충분성을 뜻하지 않으며, 이번 문서의 런타임 왕복·전투 검증을 대신하지 않는다.

## 8. 자동 직렬화 변경

빌드 또는 Unity 6 재직렬화 과정에서 다음 파일에 게임 기능과 직접 관련 없는 변경이 생겼다.

- `Assets/2.Model/Pipeline/Settings/UniversalRP.asset`
- `Assets/2.Model/Pipeline/UniversalRenderPipelineGlobalSettings.asset`
- `ProjectSettings/ProjectSettings.asset`
- `ProjectSettings/UnityConnectSettings.asset`

URP 셰이더 프리필터/런타임 설정, AppUI preloaded asset, Standalone static batching, Unity Connect 활성화 차이다. 기존 사용자 설정인지 자동 생성인지 완전히 단정할 수 없어 임의로 되돌리지 않았다. 커밋 전에 보존 여부를 별도로 결정한다.

## 9. 사용자가 직접 확인할 항목

1. 건물 앞·뒤를 걸을 때 플레이어 가림 경계가 시각적으로 자연스러운가.
2. 각 총기의 재장전 소리·시간과 탄창/예비탄 감소 체감이 적절한가.

6. 사망/생존 결과 화면의 문구, 경험치, 건너뛰기 시간이 자연스러운가.
